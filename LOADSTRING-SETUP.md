# Zebra's BL Scripts — licensed loadstring delivery

**Customer experience:** Browse the catalog → pay with Stripe Checkout → sign in → My Library → Generate loader. A unique per-product `loadstring(game:HttpGet("https://DOMAIN/api/loader/SKU?key=ZBL_..."))()` is returned. Copying or clicking Renew revokes the previous key. Bundles unlock licenses for each included product.

**Absolutely do not upload raw or obfuscated paid payloads to public GitHub.** A public GitHub raw URL is fetchable without paying, even if the Lua looks scrambled. It cannot provide access control. The six public launcher stubs live in `public-loader-repo/` and contain no source code; create one dedicated public GitHub repository for those only if desired. They require the buyer's license key, stored in `_G.ZebraLicense` by the user. Personal direct loadstrings from the website are easier.

**Seller build:** Keep raw scripts in `private-scripts/` locally. Run `npm run obfuscate` to create six encoded Lua wrappers under `protected-payloads/`. These scripts are reversible byte encoding for compatibility, not robust security. Deploy ONLY those output payloads as Render Secret Files or encrypted private object storage, never via a static/public URL. Set `SCRIPT_STORAGE_DIR=/etc/secrets` or to the private directory that contains them. Set `PUBLIC_URL=https://YOUR_MARKETPLACE_HOST` and the Stripe, Postgres, and support secrets described in README. New buyers receive Lua only after valid Stripe-linked ownership and a matching active license.

**Security limitations:** A legitimate buyer may save, debug, or share code delivered to their own client. The URL contains their license key and may leak if they share it or a service records full URLs. Rotate leaked keys in My Library and consider shorter-lived credentials, audit logging, per-key limits, automated abuse detection, and an approved professional obfuscator before commercial release. Raw source is not served by any website route. No system can guarantee Lua will never be recovered once a client executes it.

**Do not enable live checkout yet.** First confirm Stripe/Roblox eligibility for game automation and exploit-related tools, configure a test-mode key and webhook, ensure database persistence, test purchases, refunds, disputes, invalid licenses and bundle entitlements, then add customer support and legal policies. Keep checkout disabled until all dependencies and actual payloads are in place.
